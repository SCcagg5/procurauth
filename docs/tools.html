Version 1.0 Command-line tools, reference programs and a library

Tools

Five command-line tools, two reference programs and a reference PEP library in Rust. They help you build and test an implementation of the protocol, for agents and for their services.

  • keycheck
  • access-token
  • access-lint
  • fake-pdp
  • access-conformance
  • reference-service
  • reference-edge
  • PEP library
  • Get them

Why a team that builds agents wants them

An agent acts with a key. A team that builds agents, or services for agents, must know two things. A service refuses a key that goes beyond the rights of its owner. A spent budget stops the agent.

  • fake-pdp gives your service a decision point with a user, the key of her agent and their limits. Its counters run in memory.
  • access-token makes the identity tokens, good and bad, that the service must check.
  • access-conformance runs the cases against your service. Each case cites the paragraph that it tests.
  • access-lint checks the action document, where the service declares its actions and limits.
  • reference-service and reference-edge show a service and an edge that pass the cases.

Seven programs, one library

The repository builds seven programs. Five are tools for you. Two are reference programs: they are the targets that the conformance cases test, and they show how an implementation can look. A reference program is not a tool for an operator. The library procurauth-pep is the eighth crate that you use.

Common rules

Option or codeMeaning
--help, -hShow the usage and exit with 0.
--version, -VShow the name and the version of the program. The five tools add the line Apache-2.0.
Exit code 0No finding. The check passes.
Exit code 1A finding, a bad key, a failed case. For fake-pdp and the reference programs: the port cannot open.
Exit code 2The command line is not valid, a file is bad, or the tool cannot read its input.
  • The command line is closed. An unknown option, or an option that occurs two times, is a usage error.
  • The results go to the standard output. The diagnostics go to the standard error. No program uses colour.
  • The five tools read no environment variable. A reference program reads one only when its configuration names it with a key that ends in _env.
  • The configuration of a program is closed: an unknown member, a duplicate member or a wrong value stops the program at start, with a message that names the key, the expected value and the value found. --print-config prints the value that applies for each key and its source, and hides each secret.
  • No program has TLS code. The tools speak plain http and refuse an https URL. Production needs TLS from another layer, or from your own PdpTransport (see the library).

keycheck

Checks the text of a key against a key format. No store, no network.

What it does

Role
Tells if a text has the form of a key. The protocol defines no format for the text of a key (3.8), so the format is an input.
Input
The key text on the standard input, never as an argument. The tool reads at most 4,096 bytes and removes one line end. The argument is a format file, a JSON document with prefix, length, alphabet and checksum.
Output
Text: good, the SHA-256 digest of the text in lower-case hexadecimal, and a hint of 4 characters at most. Or bad: with the first cause, in this order: prefix, length, alphabet, checksum. With --format json: one object on one line.

0 good key1 bad key2 usage error or unreadable input

Rules: 3.8.

Limits

  • The tool never prints the text of a key, never writes it to a log and never puts it in an error. A usage error does not show an argument. No message shows the path of the format file.
  • It reads no environment variable and makes no network call.
  • It checks the form of the text only. It does not know your keys, and it does not make keys.
  • An empty input, an input of more than 4,096 bytes and an input that is not UTF-8 give exit code 2.

Schemas: key-format.schema.json, keycheck-output.schema.json.

access-token

Makes and checks identity tokens, good ones and bad ones, for tests.

What it does

Role
make signs a token, or makes a bad token to test a service. check runs the checks of 9.2, 9.3 and 9.4 on a token, and prints one line for each of 13 checks.
Input
make: a private key in PKCS#8 PEM form (Ed25519 or P-256) and a claims file. check: a token and the configuration of a service. Both accept - for the standard input.
Output
make writes the token on the standard output. check writes the name of the check, ok, fail or skip, and a detail. A failed line ends with the rule. --format json is available on both.

0 no finding: a token is made, or each check passes1 findings2 usage error or unreadable input

Bad tokens

  • An old exp, a late iat, a long life or an absent claim: write it in the claims file. Use --allow-bad-claims to make a token with an absent claim.
  • --alg accepts Ed25519, ES256, and, to make bad tokens, EdDSA, HS256, RS256 and none. The tool always signs with the real algorithm of the key.
  • --typ, --kid, --crit and --bad-signature make the other defects of 9.2 to 9.4.

Limits

  • By default, make refuses claims that break 9.3. It makes no token and exits with 1.
  • The tool has no key generator. Make test keys with openssl. The keys in crates/access-token/examples/ are public. Never use them for a real edge.
  • The tool reads the system clock only when you do not give --now. It reads no environment variable and makes no network call.
  • The configuration file of the service has a closed schema. It refuses Authorization, Proxy-Authorization and Cookie as the token header (9.4).

Schemas: access-token-config.schema.json, identity-token-claims.schema.json.

access-lint

Checks an action document before a service publishes it.

What it does

Role
Applies 79 rules to the action document (38), to a file of grants (26) and to an answer of the options route (15). It reports every problem, not only the first.
Input
An action document, as a file or as an http URL. Optionally --grants FILE, the grants of one subject, and --options FILE, an answer of the options route or an envelope with query and answer.
Output
One line for each finding: the JSON path, the rule and a short text. A warning has the mark warning:. --format json adds the code and the full message of each finding.

0 no error (warnings are allowed)1 at least one error2 usage error or unreadable input

Rules: 5.2, 5.3, 5.3c, 5.8, 6.1, 7.1, 8.3.

Limits

  • A warning never changes the exit code. A warning shows a SHOULD, a size above the minimum of 5.3c, or a value that has no effect.
  • The tool fetches an http URL only, with one GET. It has no TLS code and refuses an https URL with exit code 2. It reads at most 64 KiB, waits 10 seconds, follows 3 redirects at most (same host and port) and reads no proxy variable.
  • The URL is the full URL of the document. The tool does not add /.well-known/procurauth/actions.
  • A file can have 8 MiB at most. The tool does not read the standard input and reads no environment variable.
  • Without a query, the tool cannot check the type or the parent of the items of an options answer.

Rules: crates/access-lint/RULES.md lists each one. Schemas: access-lint-output.schema.json, grants-file.schema.json, options-file.schema.json.

Command
access-lint [--format text|json] [--grants FILE]    [--options FILE] <document>

fake-pdp

A test decision point (PDP). A service and the conformance runner can run without a real backend.

What it does

Role
Answers as the protocol says for decisions, limits, budgets and reasons (sections 3 to 8, 11 and 12), from the fixed data of one file. It keeps its counters in memory.
Input
A data file with services (each with its action document), subjects (persons and keys with grants), counters, failures, clock and metadata. The example crates/fake-pdp/examples/datastore.json is the data of section 13 of the protocol.
Output
The AuthZEN 1.0 endpoints and the metadata on one address. One block of log for each question on the standard output. The values of the configuration go to the standard error.

0 stopped on request1 the port cannot open2 usage error or bad file

Endpoints

  • POST /access/v1/evaluation and POST /access/v1/evaluations.
  • GET /.well-known/authzen-configuration. The metadata always has the four members procurauth_usage_max_seconds, procurauth_idle_max_seconds, procurauth_evaluations_max_bytes and procurauth_evaluations_max_items (defaults 5, 30, 1,048,576 and 100).
  • The admin endpoints, with --admin only.

Failures to make

A rule of the data file or of --failures makes the PDP fail, so that a PEP can be tested against 6.9, 6.12, 10.3 and 10.6. The kinds are error_503, delay, no_answer, close, invalid_json and no_units.

Limits

  • It is a test PDP, not a production PDP. It runs one instance, keeps the counters in memory and has no store.
  • It speaks plain HTTP. It has no TLS code.
  • The admin endpoints have no protection except the credential. Enable them on a trusted network only.
  • The tool has no --format option. A body above procurauth_evaluations_max_bytes gets HTTP 413, and more items than procurauth_evaluations_max_items get HTTP 400.
  • It keeps only the SHA-256 digest of a credential and never writes a credential to a log.

Schema: fake-pdp-data.schema.json. The crate is also a library (fake_pdp::Server), and access-conformance uses it.

access-conformance

Runs the conformance cases against a PEP, a PDP or an edge.

What it does

Role
Runs the series U against a PEP, the series D against a PDP and the series E against an edge. See the page Conformance.
Input
--role pep|pdp|edge, --profile FILE (mandatory) and --url URL. The profile tells the runner how to reach and wire the target: the operations, the keys, the credentials and the listen addresses. Optionally --cases, --series, --cases-dir and --print-config.
Output
One line for each case: the id, pass, fail, warn or skip, the paragraphs and a text. A summary line ends the run. --format json writes one document (schema conformance-report).

0 each case that ran passed1 a case failed2 usage error, bad profile or data, or a target that is not reachable

Limits

  • It speaks plain HTTP. The URL has the scheme http and no path. The tool refuses an https URL.
  • For a PEP it acts as the edge and as the PDP, and for an edge as the client, the service and the PDP. It binds the listen addresses of the profile. A port in use stops the program.
  • It makes the identity tokens with the system clock. The clock of the target must agree with it, within the skew of the profile.
  • It reads no environment variable. The profile and the options are the only sources.
  • A skipped case is not a failure. A failed case of a SHOULD rule is a warning and does not change the exit code.

Schemas: conformance-profile.schema.json, conformance-report.schema.json, conformance-case.schema.json.

Command
access-conformance --role pep|pdp|edge --profile FILE    [--url URL] [--cases ID,ID,...] [--series U|D|E]    [--format text|json] [--cases-dir DIR] [--print-config]

reference-service

A small service that uses the library. It is the test subject of the series U.

What it does

Role
The datastore example of section 13 of the protocol. It has routes for hosts, databases and tables, an action document, an options route and an MCP endpoint. It is a PEP built with procurauth-pep. It is not a tool for an operator.
Input
One JSON configuration file with a closed schema. A key takes its value from the file, or from an environment variable or a file that the configuration names (_env, _file). It needs a PDP, for example fake-pdp.
Output
One line on the standard error for each request: the method, the path and the status. Never a header, a query or a body. The client never gets the cause of a refusal.

0 stopped on request, or --print-config finished1 the port cannot open2 bad command line or configuration

Limits

  • It has no TLS client. The key pdp.url takes an http URL only, and it needs pdp.allow_insecure_pdp_link. A deployment builds its own service with the library and gives it a TLS transport.
  • It keeps its data in memory. A write changes it for the life of the process.
  • Its cache_ttl_seconds is 0, so each request reaches the PDP, as the cases expect.

The file crates/reference-service/PROFILE.md maps each operation of the cases to a request of the service.

reference-edge

A small reference edge, an HTTP reverse proxy. It is the test subject of the series E.

What it does

Role
The edge of 8.3 and section 9 of the protocol and of section 6 of the MCP binding. It reads the text of a key from Authorization: Bearer, asks the PDP for the action access on the service, makes an identity token and sends the request to the service. It never sends the text of the key on. It is not a tool for an operator.
Input
One JSON configuration file with a closed schema, with the same _env and _file forms as the service. It needs the key format, a keys file (the SHA-256 digest, the subject and the owner of each key), a signing key (Ed25519 or P-256) and a PDP.
Output
One line on the standard error for each request. Never a header, a query, a body, the text of a key or a token.

0 stopped on request, or --print-config finished1 the port cannot open2 bad command line or configuration

Limits

  • It has no TLS code. It speaks plain HTTP to the client, the service and the PDP. Put a proxy that ends TLS in front of it.
  • It has no rate limit. A client can try many key texts. The format check and the digest lookup make each try cheap.
  • It opens a new connection to the service for each request. One open connection of a client uses one thread.
  • It reads the keys file at start. Restart it to load a new file. The protocol defines no key format and no keys file (3.8).
  • It does not support the header Upgrade. It answers HTTP/1.1 only.

The key token_cache_max_entries sets the table of kept tokens (9.9). With 0, the edge keeps no token. It asks the PDP for each request, also when it keeps tokens.

Reference PEP library (Rust): procurauth-pep

The seven steps of a PEP as a small API. It does not depend on a web framework.

What it does

The application gives the headers of a request. The library gives back the identity, the ceilings to apply, or the refusal with its HTTP status. The crate reference-service uses it.

It also gives the options route (5.6 to 5.8), the builder of the action document, the helpers of the MCP binding (the feature mcp, on by default) and a Clock that a test can move by hand.

The link to the PDP needs TLS in production. The library has no TLS client. HttpTransport is a synchronous HTTP/1.1 client over std::net with no TLS, and the configuration refuses an http URL unless allow_insecure_pdp_link is set. For a deployment, implement the trait PdpTransport with a TLS client.

Limits

  • No TLS client for the PDP.
  • No server. The application owns its transport and its routes.
  • No kept result of a token check (9.7). The PEP checks each token again.
  • No Search API of AuthZEN.

How to get them

Binaries

A release has archives for Linux, macOS and Windows, with SHA-256 sums. Each archive holds the seven programs. Download one, check its sum and put the programs on your path.

Binaries of version 1.0

Source

The Rust workspace is in the repository. With Rust 1.89 or later, build the seven programs with cargo build --release --workspace. Without Rust on your machine, use the Docker script scripts/cargo.sh.

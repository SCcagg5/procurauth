Repository

The repository is github.com/SCcagg5/procurauth. It is neutral: it names no product.

procurauth/
protocol/the protocol
bindings/mcp/the MCP binding
schemas/the JSON schemas, one for each document
conformance/the cases as data, the test directories, COVERAGE.md
crates/the Rust crates (see below)
scripts/cargo.sh, conformance.sh, ci.sh and msrv.sh, which run in Docker
devdocs/the architecture, for the developers of the tools
notes/decisions, questions about the protocol, and differences from the site
docs/the source of this site (GitHub Pages)
IMPLEMENTATIONS.mdthe known implementations (protocol 16.1)
Cargo.tomlthe workspace
LICENSEApache-2.0, for the code
LICENSE-TEXTS.txtCC BY 4.0, for the texts
crates/
procurauth-core/the shared library: readers, rules and checks
procurauth-pep/the reference PEP library
keycheck/tool
access-token/tool
access-lint/tool
fake-pdp/tool, and a library
access-conformance/tool
reference-service/reference program, series U
reference-edge/reference program, series E
conformance/schema-check/crate procurauth-schema-check: checks the schemas and the data files

IMPLEMENTATIONS.md lists the known implementations of the protocol (paragraph 16.1). The README of each crate describes its program and its limits. devdocs/architecture.md describes the crates, the rules of the code and the way to add a tool. notes/ keeps the decisions and the questions about the protocol.

Build

The workspace needs Rust 1.89 or later (rust-version in Cargo.toml, edition 2024). It builds the seven programs and the library.

With Rust

Build
$ git clone https://github.com/SCcagg5/procurauth$ cd procurauth$ git checkout v1.0$ cargo build --release --locked --workspace

The programs are in target/release/.

With Docker only

The script scripts/cargo.sh runs cargo in a container. Nothing is installed on your machine. It builds the image procurauth-dev:1 one time, and it keeps the registry and the build files in Docker volumes.

Docker
$ scripts/cargo.sh build --release --locked --workspace$ scripts/cargo.sh test --workspace$ scripts/conformance.sh all$ scripts/ci.sh

scripts/ci.sh runs the format check, clippy, the tests and the conformance runs, and stops at the first failure. scripts/msrv.sh checks that the workspace builds with Rust 1.89.

Releases

A git tag such as v1.0 starts the workflow .github/workflows/release.yml. It builds the seven programs for each platform below, packs each build in an archive and makes a release. Each archive holds the seven programs and the two licence files. The release has a file SHA256SUMS with the SHA-256 sum of each archive, and each archive has its own .sha256 file.

PlatformArchiveSHA-256
Linux, x86-64procurauth-tools-1.0-x86_64-linux.tar.gz.sha256
Linux, ARM64procurauth-tools-1.0-aarch64-linux.tar.gz.sha256
macOS, Apple siliconprocurauth-tools-1.0-aarch64-macos.tar.gz.sha256
macOS, Intelprocurauth-tools-1.0-x86_64-macos.tar.gz.sha256
Windows, x86-64procurauth-tools-1.0-x86_64-windows.zip.sha256

SHA256SUMS lists all the sums. The five tools show their licence with --version.

Check a download

Linux x86-64
$ REPO=https://github.com/SCcagg5/procurauth$ BASE=$REPO/releases/download/v1.0$ curl -LO $BASE/SHA256SUMS$ curl -LO $BASE/procurauth-tools-1.0-x86_64-linux.tar.gz$ sha256sum --check --ignore-missing SHA256SUMSprocurauth-tools-1.0-x86_64-linux.tar.gz: OK$ tar -xzf procurauth-tools-1.0-x86_64-linux.tar.gz$ ./procurauth-tools-1.0-x86_64-linux/keycheck --version

Contribute

  1. Open an issue in the issue tracker to ask a question, to report an error or to propose a change. Cite the number of the paragraph.
  2. For a change of the text, keep the numbers of the paragraphs. A paragraph that leaves the text keeps its number with the word "Unused".
  3. For a change of a rule, add or change a conformance case that cites the paragraph, and add it to conformance/COVERAGE.md.
  4. For a change of the code, follow devdocs/architecture.md. Write one test for each paragraph that the code implements, and run scripts/ci.sh.
  5. Open a pull request. A contribution is under the licence of the files that it changes.

Write the documents in ASD-STE100 Simplified Technical English, as the specification does.

Changelog

The first release. The full changelog is the file docs/CHANGELOG.md of the repository.

  • The protocol and the MCP binding.
  • 15 JSON schemas and the conformance data: 191 cases in the series U, D and E.
  • The tools keycheck, access-token, access-lint, fake-pdp and access-conformance.
  • The reference programs reference-service and reference-edge.
  • The reference PEP library procurauth-pep in Rust.
  • Binaries for Linux, macOS and Windows, with SHA-256 sums.

ProcurAuth

ProcurAuth lets a backend manage the rights of its users and the rights of the AI agents that act for them. Version 1.0.

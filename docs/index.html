The rights of users and of their agents, from one backend

ProcurAuth lets a backend manage the rights of its users and the rights of the AI agents that act for them. It is a profile of the AuthZEN Authorization API 1.0.

An agent never goes beyond its owner

An agent acts with a key. The decision point takes the lower of the grants of the key and the rights that the owner has now. When the owner loses a right, the agent loses it at the next decision.

Limits for agents

A ceiling bounds one call, for example 30 seconds. A budget bounds many calls: per second, minute, hour or day. The decision point counts the budgets.

The backend manages everything

Users, grants, keys and the revocation of a key are in your backend. Each service asks the decision point and applies the answer, so a service stays simple.

A grant covers a branch. The resources of a service form a tree. A grant on a node covers the node and each node below it. See coverage.

One call of an agent, five steps

The agent never talks to the decision point. The edge checks its key. The service asks, and it applies the answer.

Built for agents that call tools

The MCP binding applies the protocol to an MCP server. These are its rules for an agent.

  • Binding 4.1

    The list shows what the key may use

    A tools/list names only the tools that the key may use.

  • Binding 3.5a

    An effect waits for an approval

    A tool with an effect waits for an approval. The service checks the rights at the call and counts the budget at the run.

  • Binding 5.3

    A spent budget has a readable error

    The agent gets the tool error budget_exceeded with retry_after, the seconds to wait.

  • Binding 5.1

    A refusal leaks nothing

    A refused call looks like a call to an unknown tool. It gives no reason.

  • Binding 3.6a

    Other methods ask for an action too

    A method with no tool, such as initialize or ping, asks the action mcp.session.

The tool error that an agent gets when its budget is spent (structuredContent, binding 5.3):

Tool error
{  "error": {    "code": "budget_exceeded",    "message": "The budget of this action is spent.",    "retryable": true,    "retry_after": 12  }}

The agent can read the error and wait. It learns no grant and no amount. A refused tool and an unknown tool get the same answer.

Five tools to build and to test

Each tool is a command-line program. A reference PEP library in Rust comes with them. See all tools.

  • access-lint

    Checks an action document before a service publishes it.

  • fake-pdp

    A test decision point for the tests of a PEP.

  • access-token

    Makes and checks identity tokens for tests.

  • keycheck

    Checks the text of a key. No store, no network.

  • access-conformance

    Runs the conformance cases against a PEP, a PDP or an edge.
